- (direction) Vision (pas douleur) : un vrai centre de contrôle façon Proxmox VE pour la flotte Homeport, exprimé par Vincent en session guided le 2026-08-23
- (direction) Attentes nommées : passer d'un Homeport à l'autre pour l'administrer, vue centralisée des logs et des événements, tableau de bord global sans visiter chaque Homeport
- (note) Slug proxmox-inspired-fleet proposé et accepté tacitement ; mode guided choisi
- (decision) CAP accès machine : comme Proxmox, la console donne aussi accès au dashboard web propre de chaque Homeport (équivalent de l'onglet Console d'une VM), en plus des actions hpm
- (decision) Événements = événements côté Homeport (healthz KO, restart du service, disque qui se remplit…) remontés dans la console — en plus du journal des tâches hpm
- (direction) Vincent délègue l'élargissement du périmètre : ajouter ce qui manque et ce qui, dans Proxmox, vaut d'être repris — sous réserve de sa validation de la liste
- (capability) CAP-1 tableau de bord global : état de toute la flotte (santé, version, disque, âge backup) en un écran
- (capability) CAP-2 administration par machine : actions hpm (update, restart, backup, restore, config, doctor) pilotées depuis la console
- (capability) CAP-3 accès intégré au dashboard web propre de chaque Homeport depuis la console
- (capability) CAP-4 logs centralisés : consultation/suivi des logs de toute machine, filtrables, sans SSH manuel
- (capability) CAP-5 événements Homeport (healthz KO, restart service, disque plein) remontés dans la console
- (capability) CAP-6 journal des tâches : historique central des actions hpm avec statut et sortie
- (capability) CAP-7 sauvegardes planifiées avec rétention + vue centrale des jobs et derniers résultats
- (capability) CAP-8 métriques historisées par machine : CPU, RAM, disque, température, avec graphes
- (capability) CAP-9 shell intégré vers n'importe quelle machine depuis la console
- (capability) CAP-10 gestion des mises à jour : releases disponibles vs installées, update déclenchable depuis la console
- (decision) Vincent valide les 10 capabilities et les non-goals proposés : HA/failover, migration, RBAC/multi-user, firewall, gestion stockage, virtualisation
- (constraint) Forme : app macOS native d'abord (SwiftUI, extension de l'existant) ; la console web Proxmox-like est une étape ultérieure explicite, hors de cet incrément
- (constraint) Collecte métriques/événements via Homeport lui-même : le repo frère expose une API événements/métriques que le centre consomme — pas d'agent dédié sur les Pi
- (constraint) Cerveau : backups planifiés côté Pi (systemd timer), indépendants du Mac ; le centre configure, consolide les résultats et rapatrie
- (constraint) Reconduites : socle HomePortKit, pas de secrets dans fleet.yaml, healthz via SSH local, versions taguées seulement, DMG signé/notarisé
- (constraint) Corollaire cross-repo : dépendance de version hpm↔Homeport — la console doit dégrader proprement face à un Homeport sans l'API événements/métriques
- (decision) Non-goals validés : console web (reportée), agent dédié Pi, HA/failover, migration, RBAC/multi-user, firewall, gestion stockage, virtualisation, supervision de services tiers
- (decision) Success signal validé : une journée d'administration complète depuis la seule fenêtre du centre (état global, dashboard intégré, logs, événement healthz KO remonté, update) sans SSH manuel ; backups planifiés exécutés sur les Pi Mac éteint puis consolidés
- (assumption) Flotte supposée petite (moins de ~10 machines) ; aucune exigence de scalabilité au-delà
- (assumption) Rétention des backups planifiés : reconduction des rotations existantes (3 sur machine, 10 sur Mac) sauf décision contraire
- (assumption) L'API événements/métriques sera spécifiée et livrée dans le repo Homeport ; ce spec la consomme seulement
- (question) Les événements Homeport (CAP-5) doivent-ils déclencher des notifications macOS, ou seulement s'afficher dans la console ?
- (question) CAP-8 : granularité et durée de rétention de l'historique des métriques ?
- (question) Un seul livrable (l'app menubar ouvre la fenêtre centre de contrôle) ou deux apps distinctes ?
